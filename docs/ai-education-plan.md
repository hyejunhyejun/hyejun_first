# 사내 AI 활용법 교육 — 발표자료 제작 계획

> 본 문서는 **발표자료를 만들기 위한 계획서**입니다. 슬라이드 본문이 아니라, 무엇을 어떤 순서로 만들지 정의합니다.

---

## 0. 전제 (확정됨)

| 항목 | 확정값 | 영향 |
|---|---|---|
| 대상 | **비개발 직군 포함 전사 일반 직원** | 실습 난이도 낮게, 문서·이메일·조사 업무 예시 위주 |
| 인원 | 20~40명, 강의실 1회차 *(미확정)* | 실습 방식(개별 vs 시연) |
| 시간 | **90분** (강의 60분 + 실습·Q&A 30분) | 슬라이드 분량 25~35장 |
| 사용 툴 | **Claude** | 모든 예시·화면 캡처를 Claude 기준으로 통일 |
| 산출물 | **웹 페이지(Artifact)** + 1장짜리 치트시트 | 슬라이드형 웹 페이지로 제작, 링크로 배포 |
| 사전 지식 | 대부분 "챗봇 몇 번 써본" 수준 | 도입부 길이 |

**확정에 따른 조정 사항**
- 섹션 4(직군별 시나리오)에서 **개발/데이터 직군 항목은 축소** — 1장으로 줄이고 기획·영업/CS·인사·마케팅에 배분
- 모든 프롬프트 예시는 Claude 기준 (Projects, 파일 업로드, Artifacts 기능 포함)
- 발표자료가 웹이므로 **라이브 데모를 페이지 안에 삽입** 가능 — 시연 실패 리스크가 줄어듦
- 청중이 비개발 직군이므로 API·자동화·코딩 관련 내용은 전부 제외

---

**교육 목표(측정 가능한 형태):**
수강 후 각자 자기 업무에서 AI를 적용할 지점 **1개 이상을 문장으로 적어낼 수 있다.**
→ 개념 전달이 아니라 "내일 당장 써먹기"가 목표입니다.

---

## 1. 콘텐츠 설계 (슬라이드 구성안)

총 6개 섹션. 괄호는 예상 슬라이드 수 / 소요 시간.

### 섹션 1. 왜 지금인가 (3장 / 5분)
- 업무 시간의 어디가 AI로 줄어드는가 — 문서작성·요약·정리·조사·초안
- 회사 차원의 기대효과 1장 (거창한 트렌드 얘기 금지, 우리 업무 얘기만)
- **의도적으로 짧게.** 동기부여는 3장이면 충분합니다.

### 섹션 2. AI는 무엇을 잘하고 무엇을 못하는가 (4장 / 8분)
- 잘하는 것: 초안 생성, 요약, 형식 변환, 분류, 브레인스토밍, 코드/수식 보조
- 못하는 것: 최신 사실, 사내 데이터, 숫자 정확도, 책임 판단
- **환각(hallucination) 실제 사례 1개 시연** — 말로 설명하지 말고 화면으로 보여주기
- "검토 없이 그대로 쓰지 않는다"는 원칙을 여기서 심기

### 섹션 3. 프롬프트 기본기 (6장 / 15분) ← **핵심 섹션**
- 나쁜 프롬프트 → 좋은 프롬프트 **Before/After 비교 3세트**
- 프롬프트 4요소: **역할 / 맥락 / 작업 / 출력형식**
- 실전 기법 3가지만: ① 예시 주기 ② 단계 나누기 ③ 되묻게 하기
- Claude에 파일 첨부해서 시키기 (PDF·엑셀·이미지)
- 안티패턴: 한 번에 다 시키기, 맥락 없이 시키기, 결과 그대로 붙여넣기

### 섹션 4. 직군별 실전 시나리오 (6장 / 15분)
직군별 1~2개씩, **실제 사내 업무를 익명화해서** 사용:
- 기획/전략: 회의록 → 액션아이템 추출, 자료 조사 요약
- 영업/CS: 고객 문의 응대 초안, 이메일 톤 조정
- 인사/총무: 공지문 작성, 규정 문서 Q&A
- 마케팅: 카피 변형안 10개, 채널별 리라이팅
- 공통: 엑셀 데이터 정리·요약, 긴 문서 읽고 질의응답
> 대상이 비개발 직군 포함 전사이므로 **개발·데이터 시나리오는 1장으로 축소**하고
> 위 4개 직군에 분량을 배분합니다.

**Claude 고유 기능 중 이 청중에게 유용한 것 (섹션 3~4에 녹여서 소개)**
- 파일 업로드 후 질의응답 — 긴 보고서·규정집 읽히기
- Projects — 반복 업무에 맥락을 미리 저장해두고 쓰기
- Artifacts — 표·문서·간단한 웹 결과물 바로 받아보기
> API, 코딩, 자동화 등 개발자용 기능은 다루지 않습니다.

### 섹션 5. 보안·컴플라이언스 가이드 (3장 / 7분)
- **입력 금지 정보**: 고객 개인정보, 미공개 재무, 계약서 원문, 인증정보, 소스코드(정책에 따름)
- 허용 도구 / 비허용 도구 명시
- 결과물 검증 책임은 사용자에게 있다
- 위반 시 절차 및 문의 채널
> 법무/보안팀 사전 리뷰 필수. 이 섹션은 임의로 쓰면 안 됩니다.

### 섹션 6. 실습 & 마무리 (3장 / 20분)
- 실습: "본인 업무 1개를 골라 프롬프트 작성 → 실행 → 결과 공유" (10분 + 공유 5분)
- 사내 지원 채널, 추가 학습 자료
- 마지막 슬라이드: **치트시트 1장 배포**

## 2. 산출물

| # | 산출물 | 형식 | 비고 |
|---|---|---|---|
| A | **발표자료 (주 산출물)** | **웹 페이지 / Artifact** | 슬라이드형 웹, 25~35 섹션, 링크로 배포·공유 |
| B | 발표자 스크립트 | `.docx` | 슬라이드당 3~5문장 |
| C | 프롬프트 치트시트 | A4 1장 (웹 내 인쇄용 섹션 + PDF) | 4요소 + 템플릿 5개 |
| D | 실습 워크시트 | A4 1장 | 실습 시간에 배포 |
| E | 사전/사후 설문 | 구글폼 문항안 | 효과 측정용 |

**웹(Artifact) 형식 선택에 따른 요구사항**
- 키보드 좌우키 / 스크롤로 넘기는 슬라이드 네비게이션
- 발표장 프로젝터 대비 **큰 폰트, 고대비** — 다크·라이트 양쪽 대응
- 이미지·CSS·JS 전부 인라인 (외부 요청 차단됨)
- 교육 후 사내에 **링크만 공유하면 되는 것**이 최대 장점 — 치트시트도 같은 페이지 안에 포함
- 발표장 네트워크 불안 대비: 페이지를 로컬 파일로도 내려받아 백업

## 3. 제작 단계 및 순서

| 단계 | 작업 | 산출 | 의존성 | 상태 |
|---|---|---|---|---|
| 1 | 전제 확정 (대상·시간·툴·형식) | 표 0 | — | ✅ 완료 |
| 2 | 슬라이드 아웃라인 상세화 (제목+핵심 메시지 1줄) | 아웃라인 문서 | 1 | ▶ 다음 |
| 3 | 직군별 시나리오 실제 예시 수집 | 예시 모음 | **사내 업무 샘플 필요** | ⬜ |
| 4 | Before/After 프롬프트를 Claude에서 실제 실행 후 캡처 | 스크린샷 | 3 | ⬜ |
| 5 | 보안 섹션 초안 → 법무/보안 리뷰 | 검토본 | **사내 정책 문서 필요** | ⬜ |
| 6 | 웹 발표자료 제작 (Artifact) | A | 2,3,4,5 | ⬜ |
| 7 | 스크립트·치트시트·워크시트 | B,C,D | 6 | ⬜ |
| 8 | 설문 문항 | E | 1 | ⬜ |
| 9 | 리허설 + 시간 측정 → 분량 조정 | 최종본 | 6,7 | ⬜ |

**병목:** 3단계(실제 사내 업무 예시)와 5단계(보안 정책)는 사내 자료 없이는 만들 수 없습니다.
이 둘이 비면 "AI는 좋은 것입니다"류 일반론 발표가 되어 교육 효과가 크게 떨어집니다.
자료가 늦어질 경우 **가상의 예시로 뼈대를 먼저 만들고 나중에 실제 예시로 교체**하는 방식으로 진행합니다.

## 4. 설계 원칙

1. **일반론 금지.** "AI가 세상을 바꾼다"류 슬라이드는 넣지 않습니다. 모든 예시는 우리 회사 업무 형태로.
2. **시연 > 설명.** 프롬프트 섹션은 슬라이드보다 라이브 시연 비중을 높입니다. (실패 대비 캡처본 준비)
3. **슬라이드 1장 = 메시지 1개.** 글머리표 5개 넘어가면 쪼갭니다.
4. **되가져갈 것 1개.** 치트시트가 실제 자산입니다. 슬라이드는 그날 끝.
5. **보안은 겁주기가 아니라 경계선 긋기.** 하지 말라만 있으면 안 쓰게 됩니다. "이건 마음껏 써도 된다"를 함께.

## 5. 위험 요소

| 위험 | 대응 |
|---|---|
| 청중 수준 편차가 큼 | 섹션 3까지는 전원 공통, 섹션 4는 직군별 선택 청취 안내 |
| 라이브 시연 실패 (네트워크/응답 지연) | 모든 시연 결과를 발표 페이지 안에 캡처로 미리 삽입 |
| 발표장 네트워크 문제로 웹 페이지 접속 불가 | 페이지를 단일 HTML 파일로 로컬 백업, USB 지참 |
| 90분 초과 | 섹션 4를 우선 축소, 섹션 3은 사수 |
| 교육 후 실사용으로 안 이어짐 | 2주 뒤 후속 설문 + 사내 채널에 사례 공유 코너 |
| 보안 정책과 충돌하는 내용 전달 | 5단계 리뷰를 6단계보다 먼저 완료 |

## 6. 다음 단계

1. ✅ 전제 확정 — 전사 일반 직원 / 90분 / Claude / 웹(Artifact)
2. ▶ **섹션별 상세 아웃라인 작성** (슬라이드별 제목 + 핵심 메시지 1줄)
3. 아웃라인 승인 후 → 웹 발표자료 제작
4. 병행 요청 사항 (사용자 측 준비)

   - 사내 AI 사용 정책 / 보안 가이드라인 문서
   - 참석 예정 직군 비율 (섹션 4 분량 배분용)
