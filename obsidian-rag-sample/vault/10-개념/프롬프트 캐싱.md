# 프롬프트 캐싱

같은 프롬프트 앞부분을 반복해서 보낼 때, 그 접두부를 캐시해 입력 비용과 지연시간을 줄이는 기능입니다.

## 접두부 일치가 핵심

캐시는 **프롬프트 앞에서부터 바이트 단위로 일치**하는 구간에만 적용됩니다.
앞쪽에 한 글자라도 바뀌면 그 뒤 전체가 무효화됩니다. 그래서 배치 순서는:

1. 고정된 시스템 프롬프트 / 규칙
2. 잘 안 바뀌는 참고 문서
3. 캐시 구분점(cache breakpoint)
4. 매번 바뀌는 질문, 타임스탬프, 검색 결과

## RAG에서의 적용

검색 결과는 질문마다 바뀌므로 캐시가 안 됩니다. 대신 **시스템 프롬프트와 위키 운영 규약처럼 고정된 부분**을 캐시하세요.
볼트가 작아서 전체를 컨텍스트에 넣는 구성이라면, 볼트 전체를 캐시 접두부에 두고 질문만 뒤에 붙이는 방식이 매우 효율적입니다.

## 캐시가 안 먹는 흔한 원인

- 시스템 프롬프트에 현재 시각을 넣음
- JSON 직렬화 순서가 매번 달라짐
- 도구 목록이 요청마다 바뀜

응답의 `usage.cache_read_input_tokens` 가 계속 0이면 위 세 가지를 먼저 의심하세요.
